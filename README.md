# 올림픽공원 공연 혼잡 캘린더

올림픽공원에서 공연이 있는 날, 동2, 남2, 북2 주차장이 평소보다 붐비는 오후(12~16시)와 저녁(17~22시)을 몇 주 앞서 예보하고, 올림픽수영장 강좌 시간표와 겹치는 회차를 알려 주는 정적 웹 서비스입니다. 2026년 한국체육산업개발 공공데이터 활용 경진대회 출품용 시제품입니다.

- **수강생 캘린더** (`site/index.html`): 강좌를 고르면 공연 혼잡과 겹치는 날을 달력에 표시하고, 겹치는 날을 휴대폰 캘린더(.ics)로 받을 수 있습니다. 주소 뒤에 `?course=강좌번호`를 붙이면 그 강좌가 선택된 상태로 열립니다.
- **기관 겹침 목록** (`site/agency.html`): 기간별로 겹치는 강좌 회차를 날짜와 구간 단위로 묶어 보여 주고, 전체 목록을 CSV(엑셀에서 바로 열리는 UTF-8 BOM)로 내려받습니다.
- **근거와 검증** (`site/evidence.html`): 2025년 실제 주차 기록으로 확인한 겹침 규모와, 한 달씩 번갈아 시험한 예보 정확도를 공개합니다.

개인정보는 받지도 저장하지도 않습니다. 서버 없이 GitHub Pages에서 동작합니다.

## 기관 담당자용 운영 방법

공연 일정이 확정되면 `data/schedule.csv`에 한 줄씩 추가하고 저장소에 반영(commit)하면 됩니다. GitHub Actions가 테스트를 돌린 뒤 예보, 겹침 목록, CSV, 캘린더 파일을 다시 계산해 Pages에 배포합니다. 테스트가 실패하면 배포하지 않으므로 기존 화면이 그대로 유지됩니다. 매일 오전 6시 17분(한국 시간)에도 자동으로 다시 계산해 예보 시작일을 하루씩 옮깁니다.

`data/schedule.csv`의 열은 다음과 같습니다.

| 열 | 예시 | 설명 |
|---|---|---|
| `date` | `2026-12-05` 또는 `2027-01-09~2027-01-11` | 공연 날짜. 물결표로 이어진 기간은 하루씩 펼쳐서 계산합니다. |
| `start_time` | `19:30` | 시작 시각. 비워 두면 19시 시작으로 보고, 화면에 '시작 시각 미정'으로 표시합니다. |
| `venue` | `KSPO DOME` | 공연장. 예상 관객 수가 없을 때 규모를 정하는 데 씁니다(KSPO DOME은 대형, 티켓링크 라이브 아레나와 핸드볼경기장은 중형, 그 밖은 소형). |
| `title` | `2026 비 (RAIN) CONCERT [THE SMOKE]` | 공연명. 화면과 CSV에 그대로 나옵니다. |
| `expected_audience` | `12000` | 예상 관객 수(선택). 있으면 공연장 기본값보다 우선합니다(5,000명 미만 소형, 15,000명 미만 중형, 그 이상 대형). |
| `source` | 공연 안내 페이지 주소 | 출처(선택). |

예보 기간은 내일부터 `schedule.csv`의 마지막 공연일까지입니다. 일정이 끝나 가면 다음 달 공연을 미리 넣어 두어야 예보가 이어집니다.

## 로컬에서 실행

```bash
pip install -r requirements.txt
python -m pytest -q
python -m olpark.build --out site/data
cd site && python -m http.server 8000
```

브라우저에서 `http://localhost:8000`을 엽니다.

## 예보 방법 요약

- 평소 패턴: 2025년 정상 기간(1~7월, 10월) 주차대수에서 공연 시간대를 뺀 월, 요일 유형(평일, 토요일, 일요일과 공휴일), 시각별 중앙값.
- 공연 효과: 과거 비슷한 공연일(규모, 평일과 주말, 공연 시작 전후 시각)의 실제 주차대수 중앙값. 같은 시각에 공연이 여럿이면 가장 큰 공연의 효과만 씁니다.
- 수준: 2025년 시간대별 주차대수 상위 25%를 '붐빔', 상위 10%를 '매우 붐빔'으로 봅니다. 공연 때문에 평소보다 200대 또는 25% 이상 많아질 때만 '공연 영향'으로 표시합니다.
- 검증 결과와 한계는 근거와 검증 화면에 있습니다.

## 구조

```
olpark/      예보 계산 (load, calendar_kr, events, baseline, analog, forecast, backtest, overlap, export, build)
tests/       pytest
data/        schedule.csv(운영자가 고치는 파일), raw/(공공데이터 원본)
site/        정적 화면 (index, agency, evidence, app.js, app.css). site/data는 빌드 산출물이라 저장소에 넣지 않습니다.
```
