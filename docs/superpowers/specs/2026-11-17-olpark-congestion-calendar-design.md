# 설계 문서: 올림픽공원 공연 혼잡 캘린더 (가칭)

작성일 2026-11-17 · 대상 대회: 2026 한국체육산업개발 공공데이터 활용 경진대회 (마감 2026-12-01 18:00)

## 1. 의도와 이유

**목표는 수상이다.** 올해 대회는 아이디어 부문을 없애고 활용사례 단일 분야로 바뀌었고, 수상작은 2028년까지 운영 협조와 소스 제공이 조건이다. 심사자(1차 내부, 2차 외부)가 "기관이 그대로 가져다 쓸 수 있다"고 판단할 결과물을 낸다.

**문제:** 올림픽공원에서 대형 공연이 열리는 날, 손해를 보는 사람은 관객보다 평소처럼 수영장과 스포츠센터에 오는 수강생이다. 지금은 이들이 자기 강좌 날짜가 공연 혼잡과 겹치는지 미리 알 방법이 없다. 기존 서비스(서울 실시간 도시데이터의 12시간 인구 예측, 서울시의 행사일 수동 공지, 해외 유료 B2B 서비스 PredictHQ)는 이 공백을 메우지 않는다.

**해법:** 2025년 기관 데이터로 "공연이 있으면 몇 시에 주차장이 얼마나 더 차는지"를 학습하고, 공연 일정표를 넣으면 몇 주 앞의 시간대별 혼잡 수준을 예보한다. 이 예보를 강좌 시간표와 겹쳐 시민용 공개 캘린더와 기관용 '강좌별 겹침 목록'으로 내보낸다.

## 2. 목표, 비목표, 실패 조건

**목표**
- 기관 공개 데이터 2종 이상(연계 데이터, 올림픽수영장 강좌정보)을 핵심 기능에 실제로 쓴다.
- 2025년 데이터로 예보 정확도를 실측해 기획서에 숫자로 적는다.
- 기획서 1-3 항목에 넣을 수 있는, 실제로 작동하는 웹 주소를 만든다.
- 운영비 0원 구조로 기관이 소스를 받아 바로 운영할 수 있게 한다.

**비목표**
- 실시간 주차 안내(실시간 API는 총합 1개 값뿐이라 이번 범위에서 제외, 검증 보조로만 검토)
- 관객용 서비스(티켓, 좌석, 귀가 안내)
- 개인 연락처 수집과 직접 알림 발송

**실패 조건 (작동해도 실패로 보는 경우)**
- 근거 없는 "AI 기반 혁신" 문구나 출처 없는 숫자가 기획서에 들어간다.
- 실제로는 영향이 작은 평일 저녁까지 "혼잡"으로 표시해 이용자가 경고를 무시하게 만든다.
- 개인정보를 다뤄 기관이 넘겨받기 부담스러운 구조가 된다.

## 3. 데이터 실측 결과 (2026-11-17 확인)

**연계 데이터 (API_CPM_009, 7,803건):** 2025년 시간대별 주차대수, 방문객, 기온, 풍향, 강수량, 습도, 휴일, 공연명, 공연관람객수. 확인된 사항은 다음과 같다.
- 1~7월과 10월은 거의 매시간 값이 있고 수준도 현실적이다(평일 낮 최고 약 2,400대, 최댓값 4,359대).
- 8~9월은 공연일에도 최고 수백 대 수준으로, 다른 달의 약 1/4이다. 집계 대상 주차장 변경이나 공사가 원인일 수 있다. 원인 확인 전에는 학습에서 제외하거나 별도 보정한다.
- 11월 8일 이후는 값이 1씩 줄어드는 일련번호 형태로 바뀌어 실제 측정값으로 볼 수 없다. 11~12월은 사용하지 않고, 기획서의 '데이터 개선 의견'에 적는다.
- 방문객은 대부분 주차대수의 정확히 3배라 독립 정보가 아니다. 사용하지 않는다.
- 공연관람객수(최대 26,398명)가 있어 공연 규모 변수로 쓸 수 있다.
- 같은 API 응답에 차량별 입출차 원자료(입구, 출구, 출차시간)가 섞여 있다. 이번 범위에서는 쓰지 않는다.

**예비 분석에서 나온 핵심 사실 (정상 8개월 기준)**
- 주말과 휴일: 공연이 있는 날의 일 최고 주차대수 중앙값은 2,251대, 없는 날은 1,092대로 약 2배다.
- 평일: 일 최고값은 공연 유무와 관계없이 약 2,400대(낮 시간대)다. 18~21시만 보면 공연이 있을 때 중앙값 1,432대, 없을 때 1,163대로 약 23% 높다.
- 정리하면 공연의 영향은 주말과 대형 공연에 집중되고, 평일 저녁 영향은 작다. 서비스는 이 차이를 그대로 보여줘야 한다.

**올림픽수영장 강좌정보 (7,133건, 2025년 개설분 2,019건):** 강좌명, 요일, 시작·종료 시간, 정원, 월별 개설 기간이 있다. "월~금,(토)"처럼 토요일 선택 수업이 붙은 강좌가 많아(2025년 993건), 주말 공연과 겹치는 지점은 주로 토요일 수업이다.

**앞으로의 공연 일정:** 공공데이터로는 없다(영문 공연정보에는 날짜와 장소가 없음). 올림픽공원 홈페이지 일정안내에는 공연명, 기간, 공연장이 공지된다.

## 4. 검토한 방식과 선택

| 방식 | 내용 | 장점 | 단점 |
|---|---|---|---|
| 1 | 공개 캘린더 + 강좌 선택 + 캘린더 구독 | 개인정보 없음, 서버 불필요 | 수강생이 찾아와야 함 |
| **2 (선택)** | 방식 1 + 기관용 강좌별 겹침 목록 | 기관 기존 연락망으로 안내 가능, 실제 업무 적용 사례를 보여줌 | 작업량 소폭 증가 |
| 3 | 카카오톡·문자 직접 알림 | 가장 편리 | 연락처 수집, 발송 비용, 2028년까지 개인정보 책임 |

사용자가 방식 2를 선택했다. 호스팅은 정적 웹사이트(A안)로 이미 정했다.

## 5. 결정된 설계

**혼잡 수준 정의 (내 판단, 이유 포함):** 세 주차장의 총 주차면 수를 아직 모르므로 "만차율" 대신 2025년 정상 기간 전체 시간대 분포의 백분위로 수준을 정한다. 상위 10% 이상은 '매우 붐빔', 10~25%는 '붐빔', 나머지는 '보통'으로 둔다. 총 면수를 확인하면 만차율 표시를 추가한다. 평일 낮은 공연이 없어도 원래 상위 구간에 들기 때문에, 화면에는 수준과 함께 '평소 같은 요일·시간 대비 공연으로 늘어난 대수'를 따로 보여준다. 기관용 겹침 목록에는 수준이 '붐빔' 이상이면서 공연으로 인한 증가분이 기준 이상인 회차만 넣어, 원래 붐비는 시간을 공연 탓으로 경고하지 않는다.

**예보 방법:** 기준선은 공연이 없는 시간의 월, 요일 유형(평일/토/일·휴일), 시간대별 중앙값이다. 공연 효과는 공연 시작 시각 기준 전후 시간대별 초과 대수로 학습하고, 공연관람객수 규모 구간에 따라 다르게 적용한다. 날씨는 몇 주 앞을 알 수 없으므로 예보에 넣지 않고, 영향 크기만 분석 결과로 보고한다. 복잡한 모델은 기준선보다 확실히 나을 때만 쓴다.

**검증:** 1~7월로 학습하고 10월로 시험한다. 평균 오차(대수), '붐빔 이상' 시간 적중률, 공연이 없는 날의 오경보율을 기획서에 그대로 적는다.

**산출물**
- 시민용 화면: 월 캘린더(날짜별 최고 수준), 날짜를 누르면 시간대별 예보, 강좌 선택 시 겹치는 날짜 강조, 강좌별 .ics 캘린더 구독 파일.
- 기관용 화면: 기간을 고르면 '붐빔 이상'과 겹치는 강좌 회차 목록(강좌명, 날짜, 시간, 정원)과 CSV 내려받기.
- 2025년 실적 화면: "2025년 실제로 공연 혼잡과 겹친 강좌 회차 수와 정원 합계"를 보여주는 근거 페이지. 기획서 핵심 수치의 출처.

**일정 입력:** 시제품은 홈페이지 일정안내에 공지된 2026년 12월~2027년 2월 공연을 CSV로 정리해 넣고 출처를 표시한다. 운영 시에는 기관이 대관 일정표(날짜, 시작 시각, 공연장, 예상 관객 수)를 같은 형식의 CSV로 올리면 재계산된다. 기획서에 '공연 일정 공공데이터 개방'을 추가 개방 제안으로 넣는다.

**기술 구조:** Python으로 전처리, 예보, 겹침 계산을 하고 결과를 JSON과 .ics로 미리 생성한다. 화면은 정적 HTML/JS로 GitHub Pages에 올리고, 일정 CSV가 바뀌면 GitHub Actions가 다시 계산한다. 서버와 데이터베이스는 없다.

**기획서:** 공고 양식(요약 1장, 상세 10장 이내)의 항목 순서를 따른다. 모든 수치는 분석 스크립트 결과에서만 가져오고, 데이터 한계(8~9월 수준 변화, 11~12월 이상값, 총 면수 미확인)를 명시한다. 제출 형식은 HWP 또는 DOCX다.
