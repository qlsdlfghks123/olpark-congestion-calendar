## 1. 현재 프로젝트 분석

### 구조
- 정적 사이트 3쪽(`index.html` 수강생 캘린더, `agency.html` 기관 겹침 목록, `evidence.html` 근거와 검증), 공용 `app.css`(366줄)와 `app.js`(571줄, 의존성 없음), Pretendard 자체 배포.
- 데이터는 Python 파이프라인(`olpark/`)이 GitHub Actions에서 매일 만들어 `site/data/`에 둡니다(저장소에 넣지 않음): `forecast.json`(날짜 x 오후/저녁 구간별 수준, 예상 최대 대수, 평소 대수, 공연 영향 여부, 공연 일정, 공휴일), `courses.json`(290개 강좌), `overlaps.json`(겹치는 회차 739개), `agency_overlaps.csv`, `ics/*.ics`, `evidence_2025.json`, `metrics.json`, `sources.json`.

### 지켜야 할 기능 (Phase 4 회귀 테스트 목록)
1. 강좌 검색 콤보박스(여러 단어 AND 검색, 위아래 화살표, Enter, Esc, 일치 부분 강조, 결과 없음 안내)
2. 강좌 선택 상태 유지(`?course=강좌번호` 주소, localStorage `olpark.course`)
3. 달 고르기(예보 기간의 달 버튼), 날짜 칸 누르면 상세, 공휴일과 일요일 표시
4. 내 수업 겹침 계산 표시(정규 수업과 토요일 선택 수업 구분), 겹치는 날 바로가기, `.ics` 내려받기
5. 다가오는 공연 혼잡 목록(8일, 모두 보기 토글, 누르면 해당 날짜로 이동)
6. 기관 화면: 기간 필터, 토요일 선택 수업 제외, 날짜와 구간 묶음 표, 50회씩 더 보기, 요약 문장, CSV 내려받기
7. 근거 화면: 월별 막대, 검증 덤벨 차트(툴팁, 키보드 초점), 전체 수치 표, 한계 목록
8. 바닥글 데이터 출처와 기준 설명

## 2. 디자인 방향

**한 문장:** 달력의 날짜 칸마다 12시부터 23시까지의 실제 시간축 막대를 놓고, 공연 혼잡 구간은 주황으로, 내 수업은 그 시간 위치에 남색 눈금으로 찍는다. 겹침은 '주황 위의 남색 눈금'으로 한눈에 보인다.

- **Civic Data:** 숫자에 단위와 기준을 붙인다(대, 평소 대비, 2025년 상위 25% 1,965대). 출처와 한계를 화면 안에 둔다.
- **Premium Editorial:** 장식 대신 글로 말한다. 달 제목 아래 한 문장 요약('붐빌 날 9일, 그중 내 수업과 겹치는 날 6일'), 상세는 제목, 요약문, 도표, 본문, 각주 순서의 기사 구조.
- **하나의 문법, 두 크기:** 칸 안의 8px 막대와 날짜 상세의 20px 시간축 도표, 다가오는 목록의 막대가 같은 컴포넌트입니다. 사용자는 한 번 배운 기호로 세 곳을 읽습니다.

### 핵심 결정
1. **주황(#E87329)은 '공연 혼잡'의 뜻으로만 씁니다.** 단추나 링크에 쓰지 않습니다. 주 동작은 남색입니다. 주황이 나타나는 곳은 곧 붐비는 곳입니다.
2. **혼잡 수준은 한 색상의 명도 단계**(붐빔 #E87329, 매우 붐빔 #9A3412)로, 색각 이상이 있어도 밝기 차로 구분되고 항상 글자('공연으로 붐빔')가 함께 붙습니다. 일요일 빨강과 혼잡이 더 이상 겹치지 않습니다.
3. **시간을 추상 레인이 아니라 실제 축으로.** 오후(12~17시, 5시간)와 저녁(17~23시, 6시간)을 길이 비율대로 그려 수업 눈금이 실제 시각에 놓입니다.
4. **내 수업의 리듬은 옅게, 겹침은 진하게.** 수업이 있는 평일은 옅은 남색 눈금, 겹치는 날만 진한 눈금과 '내 수업 19:00' 글자. 기존 디자인에서 20칸 넘게 칠해지던 파란 테두리를 대체합니다.
5. **공연 일정은 모든 날에 보이되, 붐빌 때만 강조.** 공연은 있으나 혼잡이 아닌 날(예: 12월 4일 KSPO DOME)은 회색 한 줄 공연명과 회색 막대. '공연이 있어도 괜찮은 날'이라는 정보 자체가 유용합니다.
6. **판 하나.** 흰 작업 판 하나에 달력과 오른쪽 단을 1px 선으로 나눕니다. 카드 묶음, 그림자, 그라데이션이 없습니다.

### 간격, 모서리, 깊이
- 간격 4의 배수: 4, 8, 12, 16, 20, 24, 28, 32, 40, 48. 구역 제목 위는 40, 아래는 12.
- 모서리 세 단계: 막대와 눈금 2px, 입력과 단추와 안내 상자 8px, 작업 판 12px.
- 그림자는 펼침 목록(콤보박스 결과)에만. 나머지는 선과 바탕 단계로 나눕니다.

### 레이아웃 그리드
- 데스크톱(1280 이상): 바깥 여백 32px, 작업 판 = 달력 단(가변) + 오른쪽 단 400px. 1440에서 달력 칸은 약 133 x 114px.
- 1024~1279: 오른쪽 단 360px, 다가오는 목록의 수준 열 숨김(막대와 접근성 이름으로 대체).
- 태블릿(768~1023): 한 단. 순서는 내 강좌, 달력, 날짜 상세, 다가오는 목록.
- 휴대폰(767 이하, 기준 390): 칸 66px에 날짜 숫자와 막대만, 달 단추는 폭 전체 44px 높이, 목록 행은 두 줄.

### 컴포넌트
- **하루 막대 (시그니처):** 12~23시 축, 오후와 저녁 두 구간(5:6), 혼잡 없음 #E3E8EF, 붐빔 주황, 매우 붐빔 진한 주황. 내 수업 눈금은 수업 시각 위치에 남색(평소 42% 불투명, 겹치는 날 100%와 흰 테두리), 토요일 선택 수업은 속이 빈 눈금. 크기는 칸 8px, 목록 8px, 상세 20px(축 눈금과 '내 수업 19:00' 라벨 포함).
- **날짜 칸:** 날짜 숫자, 공휴일 이름, 공연명(혼잡일 두 줄 진하게, 그 밖 한 줄 회색, '외 n'), 겹치는 날 '내 수업 19:00', 아래 하루 막대. 상태: 기본, hover(바탕 단계), 혼잡일(옅은 주황 바탕), 고른 날(안쪽 2px 남색), 초점(2px 남색 링), 기간 밖(바탕색, 누를 수 없음). 접근성 이름은 기존처럼 날짜, 구간별 수준, 내 수업 겹침을 문장으로.
- **날짜 상세:** 제목, 요약문, 시간축 도표, 구간별 수치 두 열(수준, 최대 약 n대, 평소 대비), 내 수업 안내 상자, 이날 공연 목록(시각, 공연명 전체, 공연장과 규모), 기준과 대체 패턴 각주.
- **내 강좌:** 콤보박스(선택한 강좌명 표시, 지우기), 수업 요일과 시각, 대상과 정원과 강좌번호, 겹침 횟수, 달별 겹치는 날 바로가기(32px 칸, 고른 날 남색), `.ics` 주 단추.
- **분할 단추(달 고르기), 주 단추, 조용한 단추, 입력:** 표준 웹 컨트롤. 데스크톱 38~44px, 모바일 44px 이상.
- **데이터 표(기관 화면용, Phase 6에서 적용):** 같은 토큰으로 날짜와 구간 묶음 머리 행(날짜, 하루 막대, 수준 글자, 평소 대비), 시간 열 고정폭 숫자, 정원 오른쪽 정렬, 머리 행 고정, 모바일은 시간과 강좌명 두 줄 행으로 접고 비고는 강좌명 옆 이름표로.

## 4. 목업 화면의 정보 위계
1. **달 제목과 한 문장 요약**(32px): 이번 달 붐빌 날 9일, 내 수업과 겹치는 날 6일.
2. **달력**: 첫 화면(1440 x 900)에 다섯 주가 모두 들어옵니다(달력 아래 끝 842px). 주황 칸이 이번 달의 패턴을, 진한 남색 눈금이 내 겹침을 보여 줍니다.
3. **오른쪽 단 위 내 강좌**: 수강생이 자기 수업부터 본다는 제품 원칙에 따라 오른쪽 단 맨 위. 답(9회)과 행동(.ics)이 함께 있습니다.
4. **날짜 상세**: 고른 날(12월 5일 토)의 구간별 혼잡, 수치, 내 수업 안내, 공연 목록. 첫 화면 안에서 시작합니다(상단 529px).
5. **다가오는 공연 혼잡**: 달력 아래 넓은 폭에서 날짜, 막대, 수준, 공연명, 내 수업을 한 줄로.
6. **바닥글**: 데이터 출처와 기준.

## 5. 데이터 정직성 메모
- **예상 관객 수:** 요청하신 항목이지만 현재 데이터에 값이 없습니다. `schedule.csv`에 `expected_audience` 열은 있으나 57행 모두 비어 있고, `forecast.json`에는 공연장으로 정한 규모(대형, 중형, 소형)만 실립니다. 그래서 목업은 'KSPO DOME, 대형 공연'처럼 규모를 보여 줍니다. 관객 수를 화면에 내려면 빌드 파이프라인이 그 열을 내보내도록 바꾸는 데이터 작업이 따로 필요합니다(디자인 변경과 분리).
- **공연 시간:** 시작 시각만 있습니다(종료 시각 없음). 시작 시각이 비면 '미정'으로 표시합니다.
- **내 강좌:** 현재 서비스는 강좌를 한 번에 하나만 고릅니다. 여러 강좌 등록은 없는 기능이라 목업에도 넣지 않았습니다.
- **매우 붐빔:** 이번 예보 기간에 공연 영향으로 '매우 붐빔'인 구간은 없습니다. 범례와 시스템에는 있지만 목업 화면에 지어내 넣지 않았습니다.
- 새로 보이는 요약(달 제목 아래 일수, 겹침 일수, '외 n', 이날 공연 수)은 모두 기존 데이터에서 센 값입니다.

## 6. 스킬 사용 여부
- **Impeccable:** 설치되어 있어 사용. 기존 PRODUCT.md와 DESIGN.md를 불러오고, 이번 요청을 '재설계(기존 수영장 시간표 세계를 새 세계로 교체)'로 판단했습니다. 방향은 요청서가 세계(Civic Data x Editorial, 색, 글꼴)와 첫 화면 구성을 모두 고정했으므로 무작위 방향 뽑기 없이 '사용자가 고정한 방향'으로 진행했습니다. 업무 화면(Operate)이라 이미지 생성이 아니라 실제 HTML로 만든 목업을 기준으로 삼습니다. 승인 후 구현이 끝나면 별도 검토 에이전트로 마감 검토를 하고 DESIGN.md를 새 시스템으로 다시 씁니다.
- **UI UX Pro Max:** 설치되어 있어 접근성, 터치 영역, 대비, 차트 규칙 점검표로 사용.
- **Frontend Design:** 설치되어 있어 흔한 AI 디자인 습관(크림 바탕, 눈썹 라벨, 가운뎃점 나열, 카드 묶음) 점검에 사용.
